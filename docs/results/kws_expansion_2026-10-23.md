# Модульное расширение KWS (P-001) на DS-CNN: первые результаты

Дата: 2026-10-23. Стенд: RTX 3080 Laptop, WSL, torch 2.14 cu130. Данные: Speech Commands v2,
log-mel 40 × 49 (16 кГц, окно 30 мс, шаг 20 мс), кэш `audio/kws/cache.py`.
Скрипты: `audio/kws/run.py` (база), `audio/kws/expand.py` (ветка). JSON и чекпоинты в
`results/` (не в git), имена файлов как в колонке «run».

Протокол: база DS-CNN 64×4 обучается на 8 словах {yes, no, up, down, left, right, on, off}
плюс `_silence_` и `_unknown_` (25 прочих слов), слова {stop, go} из пула исключены
полностью. Затем база замораживается (включая BN), и на новые слова {stop, go} обучается
только ветка. Метрика: порог на каждое новое слово при FAR 1 % на всех нецелевых клипах
тестового сплита (другое новое слово, прочие слова, тишина), FRR по новым словам, макро.
«Без гейтинга» = ветка оценивается сама по себе; «с гейтингом» = правило «сначала ядро»
(ядро срабатывает, если вероятность одного из его слов выше порога этого слова,
откалиброванного при FAR 1 % на валидации; тогда ветка не опрашивается).

## 5. Арбитраж между ядром и веткой: что проверено вечером 2026-10-23

Жёсткое правило «сначала ядро» давало 56–58 % FRR, потому что ядро срабатывает на
большинстве клипов невиданных слов. Проверены три рычага (expand k=16, 20 эпох, s0):

| база | калибровка порогов | ядро срабатывает на stop/go | FRR hard | FRR soft | FRR без гейтинга |
|---|---|---|---|---|---|
| unk1, stop/go не видела | GSC (прочие слова + тишина) | 57 % | 57.8 % | 30.6 % | **4.6 %** |
| unk1, stop/go не видела | Common Voice ru test (20k окон) | 41 % | 46.7 % | 48.3 % | 9.8 % |
| stop/go видела как `_unknown_` | Common Voice ru test | 25 % | 29.9 % | | 6.9 % |
| unk1 + 30k окон CV в `_unknown_` | Common Voice ru test | 68 % | 69.1 % | | 5.0 % |
| unk1 + 30k окон CV в `_unknown_` | GSC | 54 % | 54.9 % | | 5.0 % |

Пояснения. *Hard*: ветка не опрашивается, если ядро превысило порог одного из своих
слов. *Soft*: score = p_ветки(слово) × p_ядра(фон), без порогов ядра. *Без гейтинга*:
ветка решает сама по своему порогу.

Выводы.

1. **Трудные негативы для калибровки помогают, но не решают.** Common Voice поднимает
   пороги ядра (FRR на своих словах 6.0 % вместо 2.5 %, FAR на негативах GSC 0.44 %
   вместо 1 %) и снижает срабатывания на новых словах с 57 до 41 %. Этого мало.
2. **Калибровочные негативы обязаны быть невиданными при обучении.** Как только база
   обучена на окнах Common Voice, пороги по Common Voice падают (FRR ядра на своих
   словах 0.8 %, FAR на GSC-негативах уже 2.8 %), и ядро срабатывает на 68 % новых слов.
   То же для ветки: с окнами CV в её фоне порог по CV становится 0.03–0.05, и «FRR
   0.7 %» при этом фиктивный. Отдельный прогон `exp_k16_e20_cv30k_fp32_negcv_brcv10k_s0`
   оставлен как иллюстрация этой ловушки.
3. **Мягкий гейтинг лучше жёсткого на GSC-калибровке (31 % против 58 %), но всё равно
   в разы хуже ветки без гейтинга.** Замороженная база структурно уверена на
   акустически близких невиданных словах («go» рядом с «no»), и никакая арифметика
   над её выходом это не чинит.
4. **Рабочее правило для Костяна:** у каждой головы свои пороги при заданном FAR,
   срабатывание любой головы запускает её слово, при одновременном срабатывании
   побеждает больший нормированный score. Для FRR новых слов это ровно колонка
   «без гейтинга». Числа статьи (4.37 %), по всей видимости, именно про это: правило
   «сначала ядро» у них описано как конвейер инференса ради MAC, а не как условие
   метрики. Полной уверенности нет, в тексте статьи это не разделено.

3. **Отводы с последних блоков дешевле, чем узкая ветка:** k=8 с тремя отводами
   (2.2 КБ) проигрывает k=16 с четырьмя (6.3 КБ) один пункт, с двумя (1.4 КБ) два.
4. **Большая база воспроизводится хуже малой.** На 64×4 обе сессии совпали в пределах
   0.1 пункта, на 128×6 та же конфигурация дала 1.7 и 3.2 % (база 97.2 и 97.5 %), вся
   разница в слове «go». Для большой базы только средние по сидам; заголовок «1.7 %»
   из первой версии этого раздела был удачным сидом.
5. **Шаг 1 по времени** на базе 64×4 снижает FRR ветки с 7.7 до 4.7 % при той же памяти,
   но вдвое дороже по MAC (21 MMAC); базе он не даёт ничего (95.7 % в обоих случаях),
   выигрывает только ветка, которой достаётся более плотная карта признаков.
6. 4-битная база 128×6 не хуже fp32 (97.3–97.6 против 97.2–97.6 %), как и 64×4.
