# Развёртывание wake word на STM32F407G-DISC1

Инструкция для первого деплоя (ADR-011): int8 DS-CNN через X-CUBE-AI, фронтенд log-mel на
CMSIS-DSP, PDM-микрофон платы, срабатывание на слово показывается светодиодом, затем
импульс на пин пробуждения Jetson (ADR-006). Ниже 8 бит это следующий этап (раздел 8).

Статус пунктов: ✅ есть в репозитории, ◐ частично, ☐ не сделано. Обновлять по ходу.

## 1. Плата и бюджеты

| | STM32F407G-DISC1 |
|---|---|
| Ядро | Cortex-M4F, 168 МГц, FPU одинарной точности, DSP-инструкции (SIMD 8/16 бит) |
| Память | 1 МБ флеша, 192 КБ ОЗУ (128 КБ SRAM + 64 КБ CCM, CCM без DMA) |
| Микрофон | MP45DT02, MEMS, выход PDM, тактируется от I2S2 (PB10 CLK, PC3 DATA) |
| ЦАП / аудио | CS43L22 через I2S3 и I2C1 (для демо не нужен) |
| Светодиоды | PD12 зелёный, PD13 оранжевый, PD14 красный, PD15 синий |
| Кнопка | PA0 (синяя, User) |
| Отладка | ST-LINK/V2-A на борту; виртуальный COM-порт: проверить по UM1472 для своей ревизии, запасной путь USART2 на PA2/PA3 через внешний USB-UART |
| Питание | USB mini-B от ST-LINK; для связки с Jetson отдельное питание 5 В на пин 5V |

Ориентиры из литературы (P-002, P-009): DS-CNN S в int8 на Cortex-M7 216 МГц 12 мс на окно
вместе с признаками и 70 КБ памяти; на M4F 168 МГц ожидание 25–40 мс. Наша модель 64×4
(23k параметров, 10.6 MMAC) меньше DS-CNN S. Бюджет цели: ≤ 50 мс на окно при шаге
100 мс, ≤ 64 КБ флеша под модель и признаки, ≤ 48 КБ ОЗУ.

## 3. Экспорт модели из bitladder

Три пути по возрастанию сложности. Первый деплой идёт по пути A.

**Путь A, int8 средствами X-CUBE-AI (PTQ).** Экспортировать модель в float ONNX и отдать
X-CUBE-AI вместе с калибровочной выборкой признаков; он сам сделает int8 PTQ
(per-channel для весов, per-tensor для активаций). Наш анализатор показал, что 8 бит
без дообучения бесплатны, так что потерь не ожидается.

1. ✅ `python audio/kws/export_onnx.py --run results/<run>.json --out export/<run>.onnx [--calib export/calib.npz]`:
   запекает квантованные веса (веса := их fake-quant значения), сворачивает BatchNorm,
   снимает квантователи, экспортирует ONNX (вход `features` `(1, 1, 49, 40)` float32,
   выход `logits` `(1, 12)`, батч фиксирован 1) и сверяет с PyTorch через ONNX Runtime.
   Проверено 2026-10-26 на `kws12_fp32_s0`: расхождение логитов 1.4e-5, точность на
   калибровочной выборке совпадает.
2. ✅ `python audio/kws/export_calib.py --run results/<run>.json --n 500 --out export/calib`:
   нормализованные окна log-mel из валидации `(N, 1, 49, 40)` float32 в `.npz` и `.npy`,
   метки, эталонные логиты модели для валидации на плате, mean/std нормализации.
3. ☐ В CubeMX: X-CUBE-AI → Add network → ONNX → Quantize (int8, калибровка из npz) →
   Analyze (покажет флеш/ОЗУ/MACC) → Validate on desktop (сравнение с ONNX Runtime) →
   Generate code.

**Путь B, QAT-веса из bitladder в int8 на плате.** То же, но ONNX с QDQ-узлами
(QuantizeLinear/DequantizeLinear) с нашими масштабами, чтобы на плате были ровно
веса после нашего QAT. X-CUBE-AI принимает квантованный ONNX в формате QDQ; нужен
экспортёр `export_onnx.py --qdq`. Имеет смысл, когда путь A покажет расхождение
с PyTorch больше шума. ☐

**Путь C, ниже 8 бит.** Упакованные веса (4 бита, тернарные по 5 на байт) и свои ядра
или CMix-NN (P-007) поверх CMSIS-NN; X-CUBE-AI здесь не участвует. Это исследовательская
часть, раздел 8.

## 4. Фронтенд на плате

Параметры обязаны совпадать с `audio/kws/features.py`: 16 кГц, окно 30 мс (480
отсчётов), шаг 20 мс (320), FFT 512, 40 мел-полос от 20 Гц до 4 кГц, HTK-формула мел,
`log(mel + 1e-6)`, затем нормализация `(x − mean) / std` со значениями из
`data/kws_cache/index.json` (для текущего кэша mean −5.903, std 4.876). На окно в 1 с
приходится 49 кадров, карта признаков 49 × 40.

Конвейер на MCU:

1. ☐ I2S2 в режиме мастера-приёмника, тактовая PDM 1.024 МГц (для 16 кГц при децимации
   64), DMA в кольцевой буфер по половинам.
2. ☐ PDM2PCM: децимация 64 → PCM 16 кГц int16, блоками по 320 отсчётов (один шаг
   кадра, 20 мс). Проверить усиление: уровень речи с микрофона платы должен попадать
   в тот же диапазон, что клипы Speech Commands (пик порядка 0.3–0.5 от полной шкалы);
   иначе нормализация признаков уедет.
3. ☐ Кадр 480 отсчётов (текущие 320 + 160 из прошлого шага), окно Ханна (таблица 480
   float в флеше), `arm_rfft_fast_f32` на 512 точек (нули в хвосте), мощность по 257
   бинам.
4. ☐ Мел-фильтры: матрица 40 × 257 из `mel_filterbank()` экспортируется заранее в
   C-массив; у треугольных фильтров ненулевых коэффициентов мало, хранить в
   разреженном виде (начало, длина, веса): около 1.5 КБ float вместо 41 КБ.
5. ☐ `logf`, нормализация, квантование входа в int8 по масштабу, который сгенерировал
   X-CUBE-AI для входного тензора.
6. ☐ Кольцевой буфер признаков 49 × 40 int8 (2 КБ); инференс каждые 5–10 кадров
   (100–200 мс) по последним 49 кадрам.
7. ☐ Решение: softmax или просто argmax логитов, порог на вероятность слова, сглаживание
   по двум-трём последовательным окнам (как в microWakeWord: среднее вероятностей по
   скользящему окну), защитный интервал после срабатывания 1 с.

Проверка побитовой близости признаков (обязательно до замеров качества):

- ✅ `python audio/kws/export_testvector.py --wav <clip>.wav --out export/testvector`: PCM int16
  одного клипа как C-массив (32 КБ флеша), эталонные признаки до и после нормализации,
  и отдельный заголовок `testvector_mel_fb.h` с разреженной матрицей мел-фильтров
  (248 ненулевых весов на 40 полос), окном Ханна и параметрами фронтенда. ☐ В прошивке:
  прогнать PCM через пункты 3–5 вместо микрофона, вывести 49 × 40 по UART и сравнить. Цель: максимальное расхождение до нормализации меньше
  0.05 (в логарифмических единицах), после int8-квантования не больше одного шага.
- ☐ То же для выхода сети: X-CUBE-AI «Validate on target» на калибровочных данных.

## 5. Структура прошивки

```
firmware/stm32f407-kws/
  Core/            CubeMX: тактирование, I2S2 + DMA, GPIO (LED, Jetson), UART
  X-CUBE-AI/       сгенерированная сеть (network.c/h, network_data.c)
  Middlewares/     PDM2PCM, CMSIS-DSP
  App/
    frontend.c/h   кадрирование, FFT, мел, лог, нормализация, int8
    kws.c/h        кольцевой буфер признаков, вызов сети, пороги, сглаживание
    wake.c/h       импульс на Jetson (0.5 с на пин), светодиоды
    testvector.c   PCM эталонного клипа для проверки фронтенда (флаг сборки)
  README.md        как собрать, прошить, что мерить
```

Каталог `firmware/` добавляется в этот репозиторий, сгенерированный код X-CUBE-AI
коммитится (он нужен для воспроизводимости), бинарники нет.

## 6. Что мерить (по P-003, отдельно три числа)

Через счётчик циклов DWT (`DWT->CYCCNT`, 168 МГц):

| Величина | Как | Куда |
|---|---|---|
| фронтенд на кадр (PDM2PCM + FFT + мел + лог) | циклы между приходом блока DMA и готовностью строки признаков | мс на кадр, мс на секунду звука |
| инференс на окно | циклы вызова `ai_network_run` | мс на окно, загрузка ядра при шаге 100 мс |
| память | отчёт X-CUBE-AI Analyze (флеш весов, ОЗУ активаций) плюс `.map` файл линковщика | КБ флеша и ОЗУ всей прошивки |
| ток платы | мультиметр в разрыв перемычки JP1 (IDD) на DISC1 в режиме прослушивания | мА при 168 МГц; отдельно при пониженной частоте, если латентность позволяет |
| качество в комнате | 20 произнесений каждого слова владельцем, 30 мин фона (ТВ, радио) | FRR, FA/час, порог |

Числа складываются в `docs/results/stm32_<дата>.md` рядом с ориентирами из P-002.

## 7. Связка с Jetson (ADR-006)

GPIO платы (например PD0) → транзистор с открытым коллектором или оптопара → пин 12
хедера J14 Jetson на пин 11 (GND), импульс 0.5 с. Общая земля обязательна. Проверить на
Jetson заранее: `systemctl suspend` и ручное пробуждение кнопкой, версия Jetson Linux
не ниже 36.4.3 (проблема SC7 в 36.3, см. `hardware.md`).

## 8. Ниже 8 бит (после рабочего int8)

1. Экспорт упакованных весов из `bitladder.measure.size` (там уже есть упаковка 4 бит и
   тернарных по 5 на байт) в C-массивы с масштабами fp16 или q15.
2. Ядра: pointwise-свёртки как int8-GEMM с распаковкой весов на лету (4 бита → два
   int8 за один сдвиг), depthwise в int8 без изменений (они 8-битные и в нашей
   смешанной точности). Либо CMix-NN для 4 и 2 бит.
3. Сравнить мс на окно с int8 X-CUBE-AI. Если ядра не быстрее, выигрыш только во
   флеше, так и записать.
4. Ветка на новое слово (expand.py) как отдельный массив весов: демонстрация «новое
   слово за 1.5 КБ» на плате означает добавить массив ветки, не перепрошивая базу.

## 9. Порядок работ, когда плата на руках

1. CubeIDE, мигание светодиодом, UART-консоль: полдня.
2. Микрофон → PDM2PCM → PCM по UART → запись WAV на ПК и прослушивание: полдня.
3. Фронтенд и проверка по тестовому вектору: день.
4. Экспорт ONNX, X-CUBE-AI int8, валидация на ПК и на плате: полдня.
5. Сборка конвейера, пороги, светодиод, замеры из раздела 6: день.
6. Импульс на Jetson и видео-демо: полдня.
