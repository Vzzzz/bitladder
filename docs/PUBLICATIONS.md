## Записи

### P-001 · Яндекс: модульное расширение KWS новыми словами на замороженном бэкбоне · 2026-10-21
Источник: habr.com/ru/companies/yandex/articles/1061968 (продуктовый отчёт, Алиса) и
arXiv 2607.19918 «Scalable Keyword Spotting via Modular Network Expansion»
(Khaymonenko, Saladukha, Rak, Rostov; Interspeech 2026). Кода нет.  Тип: blog + paper
Тезис: Чтобы добавить к on-device KWS новые команды без регрессии старых, базовую сеть
замораживают целиком (включая статистики BatchNorm и основную голову), а от её
промежуточных активаций отводят лёгкую ветку (temporal conv + BN + hard-swish, конкатенация
по каналам с предыдущим блоком ветки) со своей головой на новые слова. Бюджет добавки
≤ 10k параметров при базе ≈ 150k. На Speech Commands v2 (8 базовых слов + 2 новых,
порог при FAR 1 % на Common Voice) средний FRR по новым словам 4.37 % против 6.46 % у
отдельной модели на 10k, 6.41 % у LoRA, 8.05 % у адаптеров, 22.3 % у «только голова»;
полный файнтюн даёт 2.35 % на новых, но ломает старые (FRR 69 %). В продукте: модель
0.5–1.5 МБ, предобучение на 60–100 млн неразмеченных фрагментов из логов ASR,
дообучение на 0.4–1 млн записей, сделанных вручную в квартире; результат −60 % ложных
срабатываний, −35 % CPU, −50 % RAM относительно отдельной модели.
Привязка: ADR-009 трек WW; skull-assistant P-002 / T-0xx (головы «стоп», «тише», «дальше»).
Переносится на: STM32 целиком. Бэкбон SVDF, 40 log-mel при 16 кГц, окно 25 мс, шаг 10 мс,
15.08 MMAC на секунду звука, то есть тот же класс, что DS-CNN из Hello Edge; наш фронтенд
(40 мел, 30/20 мс) совместим с точностью до параметров. Решающее правило «сначала
основная голова, новая голова только если основная сказала „фон“» дешёво реализуется на MCU.
Проверяемое следствие: воспроизвести на нашем DS-CNN: база на 8 словах GSC, ветка ≤ 10k
на 2 новых, порог при FAR 1 % на Common Voice ru; ожидание FRR в районе 4–7 %. Затем
новый для литературы вопрос: как квантование базы и ветки по отдельности (база в 4 бита,
ветка в 8) влияет на FRR новых слов. Это 2–3 часа на GPU после бейзлайна.
Вердикт: **принять как дизайн-референс трека WW**: один бэкбон, головы на слова
(«Костян» + быстрые команды), заморозка базы при добавлении слов. Цитировать: главы
«KWS на микроконтроллере» и «Модульное расширение».
Заметки: Главный урок отчёта не в архитектуре, а в данных: записи из целевой комнаты
с контекстом ≥ 2 с слева важнее, чем выбор метода дообучения. В статье эксперименты
только на английском GSC; абсолютные FRR на русском и в комнате из блога не раскрыты.
Ветка стоит больше MAC, чем отдельная модель на 10k (16.34M против 16.14M); выигрыш
по вычислениям заявлен только против адаптеров и LoRA, а по качеству против всех.
Глубина ветки: при 1–3 блоках ошибка высокая, оптимум около 4 блоков.
Обсуждение: владелец (2026-10-21) попросил начать литобзор именно с этого отчёта;
агент: для нас это ещё и аргумент за общий feature-фронтенд wake word и команд на MCU.
2026-10-23, проверяемое следствие выполнено (см. `results/kws_expansion_2026-10-23.md`):
на DS-CNN 64×4 порядок методов воспроизводится (ветка 4.6 % при k=16 / 7.9 % при k=8 в
лимите 10k, отдельная модель 24 %, только голова 92 %), ядро на своих словах 2.5 % FRR
как в статье. Новый результат: квантование базы в 4 бита и ветки тернарно не меняет FRR,
ветка на новое слово стоит 4.6 КБ. Не воспроизвелось правило «сначала ядро»: ядро
срабатывает на 56–74 % клипов невиданных слов, когда пороги калибруются на прочих
словах GSC; в статье калибровка на Common Voice, проверить на нём.
